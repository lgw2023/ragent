Left: multimodal professional-document inputs as abstract icons — PDF, Image, Table, Wide Table.

Right: a clean stack of structured evidence cards, each carrying a small provenance tag badge. These uniform evidence cards are the output that flows into Panel 2.

Main Panel 2 — "Parallel Graph Build" (teal):
This panel conveys the transactional, resumable, concurrent construction pipeline — a systems-level contribution. Show two clearly separated horizontal lanes, one above the other:
- Upper lane "Export": evidence units flow through a parallel extraction boundary (2-3 parallel arrow streams inside a dashed box) into serialized merge units (small stacked cards). This is the compute-heavy offline phase — extraction and embedding run in parallel, producing self-contained units without touching the graph.
- Lower lane "Replay": merge units flow through a transactional sequence of compact gates — "Stage" → "Snapshot" → "Merge" → "Commit" — with a small rollback arrow looping from "Merge" back to "Snapshot" to indicate atomic rollback on failure.
The "Commit" gate emits the assembled evidence into the graph (Panel 3). The visual message: heavy offline export is decoupled from a safe, transactional online assembly that can be replayed and rolled back.

Main Panel 3 — "ERC Evidence Graph" (blue + purple):
A refined heterogeneous node-link graph at center — the visual anchor of the figure. Render it as a richer, clearly-structured network (not a sparse 3-node sketch), with a readable two-layer binding:
- Semantic layer: a cluster of Entity nodes (blue circles of slightly varied size to hint at degree/importance) connected by Relation edges (purple directed arrows, a few carrying a tiny weight tick or thickness difference to imply typed, weighted relationships).
- Evidence layer: Chunk nodes (blue rounded rectangles, each with a small provenance tag mark) anchored beneath the semantic layer, bound upward to the entities and relations they support via thin gray connector edges — showing one chunk can ground multiple entities and one entity can be grounded by multiple chunks.
Use roughly 5-7 entities, 4-6 relations, and 3-4 chunks so the topology reads as a real evidence network with visible neighborhood structure, while staying clean and uncluttered.
Below the graph, three small aligned vector-index icons (cylinders or index cards) for the per-type indexes, each tied by a faint dotted line to its corresponding node type (entity / relation / chunk), making explicit that every node type is independently indexed for retrieval.

Main Panel 4 — "Hybrid Retrieval" (orange, gold cache, red gate):
A query enters from the left and splits into variant cards. Show two levels of cache acceleration along the retrieval path:
- A "Keyword Cache" chip near the variant cards: hit path reuses stored vector candidates (short arrow bypassing the retrieval streams); miss path continues into retrieval.
- A "Query Cache" chip near the output end: hit path returns a cached complete response (short arrow bypassing the entire retrieval-to-reasoning flow); miss path continues to Panel 5.
The two cache chips should be visually parallel — same shape, same size, different positions — to communicate a two-level acceleration design (candidate-level reuse vs. response-level reuse).

Between the two cache chips, show several parallel retrieval streams (chunk vector search, entity / relation vector search, graph neighborhood expansion). Each stream is not a bare arrow but a short ranked candidate list: 2-3 tiny candidate cards stacked, each carrying a small numeric score badge (e.g. ".92", ".87", ".81") and a rank position, so the reader sees retrieval produces scored, ranked candidates. The streams converge into a fusion shape (imply rank fusion — per-stream ranks recombining into one fused score), then pass through a rerank bar (show the order changing, a couple of candidates visibly swapping position with updated scores), then a red selection gate that keeps a top-k subset (a small "top-k" cutoff mark, implying coverage and diversity). Output: the selected ordered evidence cards.
These numeric score / rank micro-indicators are encouraged — they convey the quantitative retrieval process and are exempt from the text-label budget; keep them tiny and illustrative, never a dense table.
